# Stacked Levels Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Node levels from −1 to 3, with ramps between them, elevated junctions, height-aware joining
and crossing, and a drawing tool, rendering and saves to match.

**Architecture:** The height model sits in `roads/structures.ts` (`levelY`, `roadHeight`,
`levelProblem`, `tunnelMouth`). `RNode.level` and the derived `RSeg.ya`/`yb` sit in `network.ts`,
along with the height-aware `resolveEndpoint`, `layCurve`, `firstCrossing` and `splitSeg`. Input and
snapping pass a level. The renderers read `roadHeight`/`levelY`. Legacy spans keep their hump profile
and rules.

**Tech Stack:** TypeScript, Three.js, Node `.mjs` tests.

**Spec:** `docs/superpowers/specs/2026-09-25-levels-design.md`

## Global Constraints
- `LEVEL_H = 1.1`, a tunnel at −1.8, levels −1..3, 4 cells per level of ramp, a clearance gap of 0.9,
  and 0.25 as the tolerance for "the same height".
- Legacy spans (`structure ≠ 0` with both ends at ground) behave exactly as before.
- Existing suites stay green after every task.
